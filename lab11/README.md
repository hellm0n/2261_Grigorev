### Задание 2 **(1)**

*Функция* **dswap** *должна была обменивать значения своих параметров.* 
*(На выводе должно было получиться* ```3.4 1.5```.)
*В чем ошибка при написании этой функции? Как ее исправить? 
Что передавалось в параметры у исходной функции и у исправленной?* 
```
#include <iostream>
void dswap(double x, double y) {
   double t = x;
   x = y;
   y = t;
}
int main(void) {
   double x = 1.5, y = 3.4;
   dswap(x, y);
   std::cout << x << " " << y << std::endl;
   return 0;
}
```

**Ответ:**

Ошибка в том, что в исходную функцию параметры передавались по значению, поэтому обмен происходил только внутри самой функции, не затрагивая оригиналы в main. Чтобы это исправить, нужно передавать параметры по ссылке через &:

```cpp
#include <iostream>

void dswap(double& x, double& y) {
    double t = x;
    x = y;
    y = t;
}

int main(void) {
    double x = 1.5, y = 3.4;
    dswap(x, y);
    std::cout << x << " " << y << std::endl;
    return 0;
}
```

### Задание 4 **(2)**

*Напишите программу в которой будет создаваться восемь массивов из 128 целых чисел четырьмя способами,
каждым способом по два массива.
Первые два массива должны быть глобальными, вторые — локальными статическими, третьи — локальными на стеке,
четвертые — локальными в куче. Выведите адреса первого и последнего элемента в каждом массиве.

*В отчет запишите программу и скриншот ее работы.*

**Ответ:**

Глобальные и статические массивы лежат вплотную друг к другу в сегменте данных (с шагом в 512 байт), локальные на стеке — также рядом, но в другой области старших адресов, а массивы в куче выделяются динамически с небольшим отступом под служебную информацию аллокатора (или в произвольных местах) и сильно удалены от стека и сегмента данных.

```cpp
#include <iostream>

int g1, g2; // 1. Глобальные

int main() {
    static int s1, s2;        // 2. Локальные статические
    int l1, l2;               // 3. Локальные на стеке
    int* h1 = new int;        // 4. Локальные в куче
    int* h2 = new int;

    std::cout << "Global 1: " << &g1 << " - " << &g1 << "\n"
              << "Global 2: " << &g2 << " - " << &g2 << "\n"
              << "Static 1: " << &s1 << " - " << &s1 << "\n"
              << "Static 2: " << &s2 << " - " << &s2 << "\n"
              << "Stack  1: " << &l1 << " - " << &l1 << "\n"
              << "Stack  2: " << &l2 << " - " << &l2 << "\n"
              << "Heap   1: " << &h1 << " - " << &h1 << "\n"
              << "Heap   2: " << &h2 << " - " << &h2 << "\n";

    delete[] h1;
    delete[] h2;
    return 0;
}
```

*Приведенная ниже программа вызывает ошибку. Почему?*

*Что будет, если перенести объявление массива выше функции* **foo**?

*Что будет, если объявить массив с использованием ключевого слова* **static**?

*Что будет, если создать массив такого же размера с использованием* **new**?
```
#include <iostream>
int foo() {
    int x[100010001];
    return x[100010000];
}
int main() {
    std::cout << foo();
    return 0;
}
```

**Ответ:**

Программа падает из-за переполнения стека (Stack Overflow), так как массив требует около 381 МБ памяти, а размер стека обычно ограничен 1–8 МБ.

Если объявить массив выше foo (глобально) или с ключевым словом static, он разместится в сегменте данных, а при использовании new в куче. Во всех трех случаях ошибка исчезнет и программа запустится

### Задание 7 **(3)**

*Рассмотрите следующую программу. Выполните ее трансляцию, используя  компилятор g++ без
оптимизации (уровень оптимизации 0). Объясните ее работу.*
```
#include <iostream>
double &choose(double &a, bool flg) {
    double pi = 3.14;
    double &r = flg ? pi : a;
    return r;
}

int main(void)
{
    double a = 2.7;
    double &pi = choose(a, true);
    std::cout << pi << std::endl;
    double &e = choose(a, false);
    std::cout << e << std::endl;
    std::cout << pi << std::endl;
    return 0;
}
```

**Ответ:**

При компиляции без оптимизации программа вызывает неопределенное поведение, возвращая висячую ссылку на уничтоженную локальную переменную pi из choose. При первом выводе pi еще может случайно напечатать 3.14 из старой ячейки стека, но последующие вызовы (std::cout и choose(a, false)) перезаписывают эту память, поэтому повторный вывод pi выдает мусор, тогда как e корректно ссылается на живую переменную a.
