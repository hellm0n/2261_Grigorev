### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)
9
```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

**Ответ:**

Число 99.99 нельзя точно представить в двоичном формате `float`. Из-за погрешности выражение `x/10+0.001` может оказаться чуть меньше 10. Функция `int()` отбрасывает дробную часть, а не округляет.

Округление до ближайшего целого:
```python
round(x / 10 + 0.001)
```

### Задание 5. **(2)**

*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*
```
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y*=10
```
*В отчете требуется привести вычисления для оценки погрешности.*

**Ответ:**

В типе `double` число x = 1/3 хранится приближённо:
x ≈ 0.33333333333333331.

При сложении с большим y значащих цифр, описывающих малую добавку x, остаётся меньше. Затем при вычитании y теряется часть точности. Для double машинная точность около:
ε = 2⁻⁵² ≈ 2.22 × 10⁻¹⁶.

Абсолютная ошибка округления суммы имеет порядок y × ε. Когда y достигает порядка 10¹⁶, шаг между соседними представимыми числами становится больше 1, и добавка x ≈ 0.333 уже не меняет сумму. Тогда (x+y)-y может стать 0.0; раньше результат постепенно отклоняется от исходного приближения 1/3.

### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?
```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```

**Ответ:**

Для double наибольшее число примерно равно 1.797693 × 10³⁰⁸. При n = 1024 число 2¹⁰²⁴ превышает диапазон double, поэтому результат будет inf. При n = 1023 число 2¹⁰²³ ещё представимо.

Для long double результат зависит от платформы и компилятора. На многих системах диапазон больше, поэтому 2¹⁰²⁴ будет конечным

### Задание 8 **(2)**

*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

**Ответ:**

Все целые числа от 0 до 2⁵³ включительно точно представимы в double. Первое натуральное число, которое нельзя представить точно, — 2⁵³ + 1 = 9007199254740993. При преобразовании оно округляется до 9007199254740992.

Следующее число 2⁵³ + 2 = 9007199254740994 представимо точно: при таком масштабе расстояние между соседними числами double равно 2. Поэтому не каждое следующее число имеет погрешность — точно представимы числа, совпадающие с шагом сетки.

###  Задание 9 **(2)**
*Напишите программу для решения следующей задачи.*

*Даны четыре рациональных числа. (Рациональное число - это число вида*
$\frac{p}{q}$, *где* $p$ *и* $q$ - *целые числа.) Напишите программу, которая сравнит сумму
двух первых чисел с суммой двух последних чисел. Программа должна выводить* $1$, $0$ *или* $-1$
*в зависимости от результатов сравнения. Решение можно проверить в проверяющей системе*
[http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102](http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102), *задача 03.*

**Ответ:**

```cpp
#include <iostream>

using namespace std;

int main() {
    long long p1, q1, p2, q2, p3, q3, p4, q4;
    
    cin >> p1 >> q1 >> p2 >> q2 >> p3 >> q3 >> p4 >> q4;
    
    long long num1 = p1 * q2 + p2 * q1;
    long long d1 = q1 * q2;

    long long num2 = p3 * q4 + p4 * q3;
    long long d2 = q3 * q4;

    if (d1 < 0) {
        num1 = -num1;
        d1 = -d1;
    }
    if (d2 < 0) {
        num2 = -num2;
        d2 = -d2;
    }

    long long final_left = num1 * d2;
    long long final_right = num2 * d1;

    if (final_left > final_right) {
        cout << 1 << endl;
    } else if (final_left == final_right) {
        cout << 0 << endl;
    } else {
        cout << -1 << endl;
    }

    return 0;
}
```

Обе пары дробей приводятся к общему знаменателю, складываются, а после сравниваются крест на крест.
